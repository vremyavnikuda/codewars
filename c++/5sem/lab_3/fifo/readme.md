# Система визуализации дерева директорий через IPC

## Описание проекта

Проект состоит из двух программ на языке C, реализующих передачу информации о структуре директорий через различные механизмы IPC (Inter-Process Communication). Клиент сканирует дерево директорий в домашнем каталоге и передает его серверу, который выводит красивое дерево на stdout.

## Реализованные механизмы IPC

1. **Сигналы (Signals)** - сервер: `server_signal`, клиент: `client_signal`
2. **Разделяемая память (Shared Memory)** - сервер: `server_shm`, клиент: `client_shm`
3. **Семафоры (Semaphores)** - сервер: `server_sem`, клиент: `client_sem`
4. **Сокеты (Sockets)** - сервер: `server_socket`, клиент: `client_socket`
5. **Именованные и неименованные каналы (Named Pipes)** - сервер: `server_pipe`, клиент: `client_pipe`

## Компиляция

### Вариант 1: Использование скрипта
```bash
./compile.sh
```

### Вариант 2: Используя Makefile
```bash
make
```

### Вариант 3: Ручная компиляция отдельных реализаций
```bash
# Named Pipes
gcc -Wall -Wextra -O2 -o server_pipe server_pipe.c
gcc -Wall -Wextra -O2 -o client_pipe client_pipe.c

# Sockets
gcc -Wall -Wextra -O2 -o server_socket server_socket.c
gcc -Wall -Wextra -O2 -o client_socket client_socket.c

# Shared Memory
gcc -Wall -Wextra -O2 -o server_shm server_shm.c
gcc -Wall -Wextra -O2 -o client_shm client_shm.c

# Semaphores
gcc -Wall -Wextra -O2 -o server_sem server_sem.c
gcc -Wall -Wextra -O2 -o client_sem client_sem.c

# Signals
gcc -Wall -Wextra -O2 -o server_signal server_signal.c
gcc -Wall -Wextra -O2 -o client_signal client_signal.c
```

## Запуск

### Использование интерактивного меню
```bash
./menu.sh
```
Меню позволяет выбрать один из 5 методов IPC и запустить соответствующие сервер и клиент.

### Запуск отдельных реализаций

Для каждой реализации:
1. Сначала запустите сервер
2. Затем запустите клиента

Пример для Named Pipes:
```bash
# В одном терминале
./server_pipe

# В другом терминале
./client_pipe [глубина_сканирования]
```

Параметры:
- `глубина_сканирования` - максимальная глубина рекурсии (по умолчанию: 3)

Примеры:
```bash
./client_pipe       # Сканирование на глубину 3 уровня
./client_pipe 2     # Сканирование на глубину 2 уровня
./client_pipe 5     # Сканирование на глубину 5 уровней
```

Для сигнальной реализации параметры немного отличаются:
```bash
./client_signal [глубина_сканирования] [server_pid]
```

## Как это работает

### Протокол передачи данных

Во всех реализациях клиент отправляет серверу строки в формате:
```
D:уровень:имя_директории
F:уровень:имя_файла
```

Где:
- `D` - директория
- `F` - файл
- `уровень` - глубина вложенности (0, 1, 2, ...)
- `имя` - название файла или директории

### Алгоритм работы (для всех реализаций)

**Сервер:**
1. Инициализирует выбранный IPC механизм
2. Ожидает подключения клиента
3. Читает/получает данные построчно
4. Парсит каждую строку
5. Выводит красиво отформатированное дерево
6. Закрывает соединение и освобождает ресурсы

**Клиент:**
1. Подключается к серверу через выбранный IPC механизм
2. Рекурсивно сканирует домашнюю директорию
3. Отправляет информацию о директориях и файлах
4. Закрывает соединение и завершает работу

## Особенности реализации

### Каждый IPC метод реализован с учетом его особенностей:
- **Сигналы**: Используются для синхронизации, а не для передачи данных (ограничения сигнального механизма)
- **Разделяемая память**: Используется общий сегмент памяти для передачи данных
- **Семафоры**: Используются вместе с разделяемой памятью для синхронизации
- **Сокеты**: Используются UNIX domain сокеты для двунаправленной связи
- **Каналы**: Используются именованные каналы (FIFO) для односторонней передачи

### Безопасность и надежность
- Проверка прав доступа к директориям
- Обработка ошибок при открытии файлов
- Ограничение глубины рекурсии (защита от зацикливания)
- Корректная обработка символических ссылок (lstat вместо stat)

### Оптимизация
- Буферизация ввода-вывода (4KB буфер)
- Эффективная обработка больших деревьев директорий
- Минимальное использование системных вызовов

### Форматирование вывода
- Цветной вывод (директории выделены синим)
- Символы псевдографики для дерева
- Визуальные разделители

- **OS:** Linux/Unix

## Отладка

Если возникают проблемы:

1. Проверьте, что все зависимости установлены:
```bash
which gcc make
```

2. Убедитесь, что у вас есть права на создание FIFO и сокетов в /tmp

3. При зависании процессов используйте:
```bash
killall server client server_pipe client_pipe server_socket client_socket server_shm client_shm server_sem client_sem server_signal client_signal
```
